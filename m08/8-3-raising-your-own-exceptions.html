8.3 Raising Your Own Exceptions

Read: Python Unlocked, Chapter 7, "Raising Your Own Exceptions"

Sometimes the data is technically valid Python but makes no sense for your program: a negative age, a price of $0, a quantity of -3. You can raise your own exception to stop bad data:

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative!")
    if age > 150:
        raise ValueError("Age value is unrealistically high!")
    return age

try:
    print(set_age(25))
    print(set_age(-5))
except ValueError as error:
    print(f"Invalid age: {error}")

Notice the split: the function detects the problem and raises; the code that calls it decides what to do about it. That's how professional code is organized.

A real-world example: validating an order

def validate_order(product, quantity, price):
    if product.strip() == "":
        raise ValueError("product name is missing")
    if quantity <= 0:
        raise ValueError(f"quantity must be positive, got {quantity}")
    if price <= 0:
        raise ValueError(f"price must be positive, got {price}")
    return quantity * price

orders = [("Webcam", 2, 59.00), ("", 1, 10.00), ("Mouse", -1, 24.50)]
for product, qty, price in orders:
    try:
        total = validate_order(product, qty, price)
        print(f"OK: {product} x{qty} = ${total:.2f}")
    except ValueError as error:
        print(f"Rejected: {error}")

This is exactly how data pipelines work in industry: good records go through, bad records are rejected with a reason, and the program keeps running. You'll build one in the assignment.
