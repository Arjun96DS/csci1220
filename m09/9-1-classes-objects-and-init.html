9.1 Classes, Objects and __init__

Read: Python Unlocked, Chapter 8, "Classes and Objects"

So far you've organized programs with functions. Object-oriented programming (OOP) organizes them around objects, bundles of data plus the functions that work on that data. Most large software (games, banking systems, web apps) is built this way.

  • A class is a blueprint (like the design for a car).
  • An object is one thing built from the blueprint (your specific car). You can make many objects from one class.

Your first class

class Student:
    def __init__(self, name, age, gpa):
        self.name = name
        self.age = age
        self.gpa = gpa

student1 = Student("Priya Sharma", 22, 3.85)
student2 = Student("Rahul Verma", 20, 3.42)
print(student1.name, student1.gpa)
print(student2.name, student2.gpa)

What's going on

  • class Student: defines the blueprint. Class names use CapitalWords.
  • __init__ is the constructor. It runs automatically every time you create an object and sets up its starting data.
  • self means "this particular object". self.name = name stores the name inside the object.
  • self.name, self.age, and self.gpa are attributes, the object's data.

Changing an attribute

class Student:
    def __init__(self, name, age, gpa):
        self.name = name
        self.age = age
        self.gpa = gpa

student1 = Student("Priya Sharma", 22, 3.85)
student1.gpa = 3.90
print(student1.gpa)

Why bother? Encapsulation and DRY

Keeping the data and the code that uses it together is called encapsulation. Writing a blueprint once and reusing it follows the DRY principle: Don't Repeat Yourself.
